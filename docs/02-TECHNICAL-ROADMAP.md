## 1. Architectural Decisions (ADR-style, short)

### ADR-01 — Deterministic mission engine first, AI as shaper
- **Decision:** Missions are generated by a **local rule engine** (templates, day-of-week rules, streak/fatigue context, goal linkage). The OpenAI call only runs for onboarding plans, boss/plan reshaping, and weekly reviews.
- **Why:** The brief says "daily tasks generated from goals" via AI. At scale, per-user daily AI calls are a burn-rate grenade. Deterministic generation is instant, offline-able, and free; AI adds *personalization polish* only where it matters (weekly).
- **Ratio:** ~1 AI call / user / week in steady state.

### ADR-02 — Analytics pre-aggregated, not live-queried
- Raw mission/milestone events append to a per-user **event log** (bounded, 90-day retention).
- Daily/weekly/monthly **rollup docs** are computed by a Cloud Function (UTC midnight tick). All dashboards read rollups — never scans.
- Long-term BI: Firebase Analytics → BigQuery export; reports read BQ, not Firestore.

### ADR-03 — Counter integrity
- All XP / coins / streak-day counters mutate via **atomic increments** (`FieldValue.increment`), guarded by server-run transaction only for XP→level rollover.
- Deriving progress values (boss HP, skill points, level) is a pure function of stored counters. No drift.

### ADR-04 — Offline-first, eventual consistency
- Firestore offline persistence ON for the user's own collections (missions, day plans).
- Mission completion is a **client-resolved state change** with an `completedAt` + sync queue; conflicts resolve with last-write-wins per mission + an AI review cross-check later.

### ADR-05 — Time handling is UTC storage, local semantics
- All timestamps UTC. `dayKey = yyyy-mm-dd in user timezone`. Streak resets at *user-local midnight* (respect DST). One `dayStartMinute` preference per user (default 00:00, allow 06:00-24:00 shift for night owls).

### ADR-06 — Content as data, never code
- Skill trees, archetypes, missions templates, achievements catalog, boss templates: **Firestore content documents** hydrated at startup + cached. Non-engineers extend the game catalog without an app release.

### ADR-07 — AI integration is server-only
- OpenAI key lives in a Cloud Function. The client calls `callMentorAction` (typed action enum) — never the AI directly.
- Response is validated against a JSON schema; minified profile digest (top 3 stats, streak, week stats, current plan summary) is sent, **not** full chat history.
- Budget/hour & /day per user enforced server-side.

### ADR-08 — Riverpod as state layer
- Riverpod (manual + codegen for async repositories) — reactive streams from Firestore into Notifiers; providers = DI of the app. Clean layering: presentation never touches data sources directly.

## 3. Firestore Data Model (v1)

> Collections are grouped; all reads/writes confined by security rules. Counters via atomic increments only.

### 3.1 Core indices (top-level collections)

```
users/{uid}
  ├─ profile: { displayName, avatarRef, email, createdAt, tz, dayStartMinute }
  ├─ state:   { xp, level, coins, streak, bestStreak, lastDayKey, titleId, flags{} }
  ├─ stats:   { vitality, knowledge, discipline, strength, creativity, confidence, finance, relationships }  // 0-100
  ├─ config:  { notifications{}, premium }
  ├─ rollup/  { YYYY-MM-DD: { xp, missionsDone, questsDone, bossDamage } }   // daily, aggregated by function
  └─ events/  { eventId: { type, payload, ts } }   // capped & archived at 90d

users/{uid}/goals/{goalId}
  { title, category, targetDateEpoch, status,
    milestones: [ { title, dateEpoch, completedAt?, xpValue } ],
    autoGenerated, progressSignals }           // measured + effort signals

users/{uid}/missions/{YYYY-MM-DD}/list  → array of mission docs (max 8)
  { id, title, durationMin, type, statTargets[], xp, coins,
    status: pending|done|skipped, evidence: {kind, ref, url|number}?,
    completedAt, source: rule|ai, goalId? }

users/{uid}/skills/{treeId}
  { treeId, treeXp, nodes: { nodeId: { unlockedAt, level } },
    navigation: currentActiveNode }

users/{uid}/bosses/{bossId}
  { title, type: weightLoss|savings|portfolio|videos|deploy|habit,
    targetValue, currentValue, hpMax, hp: damageTaken,
    deadlineEpoch, status: active|defeated|rematch,
    eventLog: [{date, delta, reason}], rewardGranted }

users/{uid}/honors/{honorId}   // achievements + badges (single registry)
  { kind: achievement|badge|title, unlockedAt, value }

users/{uid}/mentor/{threadId, lastSummary, lastAt}   (subcollection messages bounded 60/server-truncated)
```

### 3.2 Content (CMS — CRUD by backend, read by all)

```
catalog/archetypes/{archetypeId}   // onboarding presets (6-8)
catalog/goalTemplates/{goalTemplateId}   // per-archetype goals + milestone seeds
catalog/skills/{treeId}   // trees, nodes w/ xp gates, statBonus, title
catalog/missionTemplates/{category} → templates with weights
catalog/campaigns/{bossId}   // boss snapshots: hpScale, rewards, art refs
catalog/achievements/{achievementId}   // trigger defs (severity, value, metric ref)
catalog/shop/{itemId}   // cosmetics: tier, category, price, assetRef
```

### 3.3 Security rules (essence)
- Users: `request.auth.uid == uid`
- Content catalog: read-open, write-admin-only (custom claims)
- Events/rollup: write-once they run (unless service-account)
- Cloud Functions: admin-only paths via a `service` marker claim

## 4. Backend surface (Cloud Functions / HTTPS)

| Endpoint | Purpose | Auth | Rate |
|---|---|---|---|
| GET `/plan/today?dayKey` | Compose daily plan (rules engine server-side) | user | 2/hr |
| POST `/plan/reshape` | AI re-plan after weekly review | user | 1/day in-sign-up |
| POST `/mentor/ask` | Weekly review + daily digest (typed) | user | daily: 1 review, digest 1/hr |
| POST `/boss/progress` | Record measurement/evidence for boss | user | 5/day |
| POST `/streak/claim` | Streak claim (midnight catch-up reconciliation) | user | 1/day |
| POST `/rollup/daily` | Compute nightly rollups (cron) | service | 1/day |
| POST `/notifications/digest` | Compose & schedule daily notification plan (FCM) | service | 1/day |
| GET `/export/user` | Data portability bundle (JSON) | user | on-demand |

AI-related functions validate JSON against a **tool schema**, cap tokens, cache prompt prefix (system + profile digest) in Cloud Storage, and apply per-account budget.

- Motion: 200ms standard, spring curves; reduced-motion accessibility switch.

## 6. Phased Execution Plan

### Phase 1 — Architecture & Foundations (Week 1)
- Firebase project + emulators + CI/CD (Fastlane for iOS, codemagic/GHA for Android)
- Flutter skeleton: folders, routing, theme, Riverpod setup, DI provider graph
- Firestore rules + seed index; content catalog schema; functions scaffold (empty stubs + Auth middleware)
- **Exit criteria:** app boots dark premium shell; user doc created after auth; design system visible.

### Phase 2 — Authentication + Onboarding (Week 2)
- Firebase Auth: Google, email, anonymous→upgrade, Apple (iOS)
- Onboarding: 5-screen flow w/ archetype pick → goal storyboard → plan draft → **first win in ≤90s**
- Auth gate + profile seeding; Remote Config flags
- **Exit:** new user reaches home with avatar at 24hr retention-ready.

### Phase 3 — Home (Dashboard) (Week 3)
- Home: character + streak + today quests + boss meter + next achievement
- Offline-first data reads; loading/perf budgets
- **Exit:** D1 task open-time ≤2.5s on mid-range churn.

### Phase 4 — Character System (Week 4)
- XP/Level model + stats 0–100; XP bar anim; level-up celebration overlay
- Streak engine: day key, freezing, midnight reconciliation
- Avatar assembly (initial cosmetics)

### Phase 5 — Goals & Skill Trees (Weeks 5–6)
- Goals CRUD + milestone auto-generation; progress signals
- Skill trees: catalog loader, node unlock logic, stat bonuses
- Boss scaffolding interface

### Phase 6 — Missions Engine (Week 6-7)
- Rule-engine generator + template catalog; completion w/ evidence capture (photo/link/number)
- Bad-day reroute; skip, streak-linked dynamics

### Phase 7 — AI Mentor (Week 8-9)
- Cloud functions: `plan/reshape`, `mentor/weekly-review`, `mentor/digest`
- JSON schema validation; digest composition; budgets enforced end-to-end

### Phase 8 — Achievements & Economy Shop (Week 10)
- Honors registry triggers; shop + cosmetics; coin ledger
- Streak freezes & limited handouts

### Phase 9 — Analytics & Insights (Week 11)
- Rollups functions; weekly report UI; AI narrative report
- Firebase Analytics + BQ export wiring

### Phase 10 — Hardening & Production Release (Week 12)
- Offline matrix signing; perf pass; accessibility; i18n (en, hi)
- App store assets; privacy policy connector & compliance docs
- Crashlytics alerting; release checklist (see ADR checklist below)

### Post-v1.1 (backlog, for planning)
- Leagues (weekly), friend boosts, share cards, watch/health integrations, premium tier (mentor Q&A), web/more platforms

## 9. Roadmap Gating Rules

- **Go/No-Go after Phase 3 (dashboard):** user-research or self-test 5 users, retention probe.
- **Go/No-Go after Phase 7 (AI):** cost per DAU < 1¢/day measured.
- **Go/No-Go before production release:** crash-free ≥ 99.5, D1 ≥ 45% measured vs target from §8 of PRD.
